# ESP32 + DS3231 date/time module

The prototype uses a generic DS3231 RTC breakout (HW-084 in the firmware guide).
The RTC preserves time without the Android app; it does not power the ESP32.
See [complete wiring](README.md).

| Module label | ESP32 connection |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO 21 |
| SCL | GPIO 22 |
| SQW / 32K | Unconnected |

Address is `0x68`. Some boards also contain an EEPROM at `0x57`; UVIR does not
use it. Check the actual header order, which differs between generic modules.

## Backup cell and charging

Fit a cell compatible with the **module's circuit**, not just its holder size.
The DS3231 itself is not a charger; some breakout boards add charging parts.
Never charge a non-rechargeable cell, and do not assume that any rechargeable
cell is compatible with an arbitrary breakout charging circuit. See
[Analog Devices' charging explanation](https://ez.analog.com/clock_and_timing/a/documents/do12021/does-the-ds3231-provide-trickle-charging)
and the [DS3231 data sheet](https://www.analog.com/media/en/technical-documentation/data-sheets/DS3231.pdf).

## Firmware behavior

Send `TIME <current_unix_epoch_ms>` from a trusted host to set runtime and RTC.
The firmware stores UTC; local time zones and daylight saving belong to the host
display, not a manual one-hour RTC offset. After power loss a valid RTC lets an
unfinished job resume against its original deadlines, skipping missed samples.

Inspect `rtc_available`, `rtc_valid`, `rtc_read_ok`, `rtc_current_time_ms` and
`rtc_oscillator_stopped` in `HELLO`. Capture the last flag **before** setting time.
It reports that the oscillator stopped, not a measured battery percentage or
an early low-voltage warning. Invalid time blocks durable records; the rejection
beep/LED safety indication remains enabled even with the RTC fitted.

Test retention only after synchronizing valuable records and while idle. Inspect
time after a deliberate power cycle, before a host automatically corrects it.
