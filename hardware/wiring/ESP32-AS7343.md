# ESP32 Dev Module + GY-AS734X (AS7343)

The current visible/NIR breakout is marked GY-AS734X. Its AS7343 chip was
confirmed through the driver's device-ID check during the 2026-10-12 USB
verification. The replacement uses the same logical wiring and approximate
22 × 13 mm board dimensions; exact physical pin spacing/order remains to be
checked before choosing a PCB socket footprint.

## Controller reference

The prototype currently reports an `ESP32-D0WD-V3` revision 3.1 inside an
ESP-WROOM-32 development module. Use the common 38-pin ESP-WROOM-32 Dev Module
diagram supplied with the project as the **logical GPIO reference**. It agrees
with the GPIO assignments below, but it is not an authoritative mechanical PCB
footprint: before laying out a carrier PCB, verify the exact board width, header
spacing, pin order, and USB overhang on the physical module.

The firmware's authoritative pin and I2C map is kept in
`firmware/esp32/UvirSensor/UvirHardwareConfig.h` so wiring documentation and
future PCB schematics can be checked against one source.

Initial Uvir prototype wiring:

| Signal | ESP32 | GY-AS734X / AS7343 module |
|---|---:|---:|
| I2C data | GPIO 21 | SDA |
| I2C clock | GPIO 22 | SCL |
| Ground | GND | GND |
| Supply | 3V3 only on a verified compatible breakout | VIN/VCC |

The current polling driver does not require the board's additional `I` and `G`
signal pads; leave them unconnected as in the reference build. Use the pad
explicitly marked **GND** for the ground connection.

The rest of the instrument is documented in the [complete wiring index](README.md).
The following summary is retained for older links:

| Peripheral | ESP32 | Connection |
|---|---:|---|
| RGB LED red | GPIO 25 | Through its own 330 Ω resistor |
| RGB LED green | GPIO 26 | Through its own 330 Ω resistor |
| RGB LED common cathode | GND | Direct |
| Separate blue LED anode | GPIO 27 | Through its own 330 Ω resistor |
| Separate blue LED cathode | GND | Direct |
| Passive piezo buzzer `+` | GPIO 32 | Direct for a low-current passive piezo |
| Passive piezo buzzer `-` | GND | Direct |
| External command input | GPIO 33 | Dry contact to GND; internal pull-up |

Leave the blue anode of the RGB LED disconnected. The RGB red and green
channels show connection/activity state; the separate blue LED shows pending
unsynchronized acquisitions, alerts or errors. See the [complete LED legend](ESP32-STATUS-LEDS.md).

Check the electrical specifications before using an active buzzer, magnetic
transducer, or three-pin module; it may need a transistor driver.

GPIO 33 is a 3.3 V input. A button can connect it directly to GND, but a 5 V
logic signal requires an optocoupler or a suitable protected level shifter.
The external-command input is enabled by default and can be disabled from the
sensor Management settings in the app; that choice is stored persistently on
the sensor.
One short closure records, three consecutive short closures start an external
session, and a closure held for two seconds stops the active session. A short
press can add an external record to a manual app session, but is rejected during
normal automatic acquisition or alerts. See the
[full button behavior](ESP32-EXTERNAL-COMMAND.md). A dry
contact, open-drain/open-collector output or correctly isolated industrial
controller may use the same input semantics.

The AS7343 silicon uses a 1.8 V supply and 1.8 V I/O. Many breakout boards add
a regulator and level shifting, but the exact GY-AS734X module must be checked
before it is connected to 3.3 V. A product photo alone is not enough to prove
the electrical design.

For the chip's electrical limits, see the
[ams OSRAM AS7343 data sheet](https://look.ams-osram.com/m/5f2d27fff9a874d2/original/AS7343-14-Channel-Multi-Spectral-Sensor.pdf).

For the first Android test the ESP32 is connected to the phone through a USB
OTG data adapter/cable. Its CP210x USB-to-UART bridge identifies itself as
VID `10C4`, PID `EA60`.

## Verification and optical assembly

The expected I2C address is `0x39`, and the current driver checks chip ID `0x81`.
Check `sensor_available` and the AS7343 driver state in diagnostics, not only a
bus acknowledgement. All four I2C peripherals share GPIO 21/22; inspect combined
pull-ups before adding more modules. Do not replace this board with an AS7341
merely because its library symbol or seller title looks similar.

Fit the board with its long edge horizontal as intended, but measure its actual
socket pin order and row spacing. Isolate its optical face from status LEDs and
other module power LEDs. Final dark/reference calibration must use the assembled
enclosure and optics; see the [calibration plan](../calibration/README.md).
