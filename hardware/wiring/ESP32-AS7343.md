# ESP32 Dev Module + GY-AS7343

## Controller reference

The prototype currently reports an `ESP32-D0WD-V3` revision 3.1 inside an
ESP-WROOM-32 development module. Use the common 38-pin ESP-WROOM-32 Dev Module
diagram supplied with the project as the **logical GPIO reference**. It agrees
with the GPIO assignments below, but it is not an authoritative mechanical PCB
footprint: before laying out a carrier PCB, verify the exact board width, header
spacing, pin order, and USB overhang on the physical module.

The firmware's authoritative pin and I2C map is kept in
`firmware/esp32/UvirSensor/UvirHardwareConfig.h` so wiring documentation and
future PCB schematics can be checked against one source.

Initial Uvir prototype wiring:

| Signal | ESP32 | AS7343 module |
|---|---:|---:|
| I2C data | GPIO 21 | SDA |
| I2C clock | GPIO 22 | SCL |
| Ground | GND | GND |
| Supply | verify module first | VIN/VCC |

Optional status outputs:

| Peripheral | ESP32 | Connection |
|---|---:|---|
| RGB LED red | GPIO 25 | Through its own 330 Ω resistor |
| RGB LED green | GPIO 26 | Through its own 330 Ω resistor |
| RGB LED common cathode | GND | Direct |
| Separate blue LED anode | GPIO 27 | Through its own 330 Ω resistor |
| Separate blue LED cathode | GND | Direct |
| Passive piezo buzzer `+` | GPIO 32 | Direct for a low-current passive piezo |
| Passive piezo buzzer `-` | GND | Direct |

Leave the blue anode of the RGB LED disconnected. The RGB red and green
channels show connection state; the separate blue LED shows active operations
and newly recorded acquisitions or alerts.

Check the electrical specifications before using an active buzzer, magnetic
transducer, or three-pin module; it may need a transistor driver.

The AS7343 silicon uses a 1.8 V supply and 1.8 V I/O. Many breakout boards add
a regulator and level shifting, but the exact GY-AS7343 module must be checked
before it is connected to 3.3 V. A product photo alone is not enough to prove
the electrical design.

For the first Android test the ESP32 is connected to the phone through a USB
OTG data adapter/cable. Its CP210x USB-to-UART bridge identifies itself as
VID `10C4`, PID `EA60`.
